# Первый запуск Pi Agent Kit

## Установка в папку на D

1. Помести репозиторий в отдельную папку, например `D:\Projects\ActiveProjects\AIProjects\pi-agent-kit`.
2. Запусти `install.cmd`. В мастере укажи отдельную папку своего проекта, например `D:\Projects\my-pi-project`. При первой установке нужен интернет.
3. Мастер подготовит Pi рядом с шаблоном и скопирует кит в выбранный проект. В открывшемся конфигураторе выбери подключения Чифа, исполнителей и Bug Fixer.
4. Сохрани настройки и подготовь Pi. Затем закрой конфигуратор и запусти `start.cmd` **в папке своего проекта**.

Установщик закрепляет Pi на версии 1.3.0 в `.tools/pi` папки шаблона. Кеш npm
лежит рядом, в `.tools/npm-cache`. Установленный проект сохраняет путь к шаблону
в `.pi/installation.json`; не удаляй шаблон после установки. Несколько проектов
могут использовать одну установку Pi. Нужен Node.js 22 или новее;
установка Pi не меняет глобальные npm-пакеты. Если Node не найден, установщик
сообщит об этом. Не устанавливай другой Node наугад: сначала прочитай сообщение.

Кит использует закреплённый Python 3.13.16 с Tk через `kit\python.cmd`.
`install.cmd` и `start.cmd` по умолчанию задают `PI_KIT_RUNTIME_HOME` как
`.tools\python-runtime` рядом с запускаемым файлом. Поэтому при размещении
шаблона и проекта на D новые файлы Python также остаются на D.
Можно заранее задать `PI_KIT_RUNTIME_HOME` на общую папку на D для нескольких
проектов. Системный Python не изменяется.
Размер `.tools`, рабочих копий и истории стоит проверять по мере использования.
Копии больших проектов занимают больше места, чем сама программа кита.

![Порядок установки и настройки](../../readme_gif/pi_install.gif)

Это схема действий. Здесь нет записи установки на конкретном компьютере.

## Выбор подключения

Если выбираешь встроенного провайдера Pi, сначала подключи его **в своём проекте**:

```powershell
.\start.cmd --authenticate
```

На Linux соответствующая команда — `sh start.sh --authenticate`.
Откроется настоящий Pi для настройки доступа. Введи `/login`, выбери провайдера
и пройди его вход или введи ключ. Затем выйди командой `/quit`.
Для выхода также можно нажать `Ctrl+C` дважды. После этого открой конфигуратор:

```powershell
.\start.cmd --configure
```

Обнови каталог моделей Pi, назначь модели ролям, сохрани и подготовь настройки.
Этот шаг нужен для источника `pi`; собственный API настраивается в форме,
как описано ниже.

Запуск `--authenticate` использует `PI_CODING_AGENT_DIR` именно этого проекта:
`.pi/agent`. Ранее выполненный глобальный вход Pi не подхватывается.
Учётные данные сохраняются в `.pi/agent/auth.json`; эта папка исключена из Git
и при размещении проекта на D остаётся на D. Не копируй её в публикуемые архивы.
Режим входа не создаёт сессию кита; инструменты, расширения, MCP, навыки,
шаблоны промптов и темы отключены. Используй его для `/login`, затем вернись
к обычному `start.cmd` для работы над задачей.

Для собственного API укажи адрес, идентификатор модели и имя переменной ключа.
Кнопка сохранения ключа записывает его в пользовательское окружение Windows;
в JSON остаётся имя переменной. Подготовка Pi связывает подключения с ролями.

Исполнителям можно назначить загруженный экземпляр LM Studio. Сначала загрузи
модель в LM Studio и включи локальный сервер. В конфигураторе выбери конкретный
экземпляр: это позволяет отправлять запросы именно к уже загруженной модели.

Витрина OpenRouter помогает выбрать модель и перенести её в нужную роль.
После этого проверь адрес и ключ выбранного подключения. Доступность модели
зависит от аккаунта провайдера. Ответ списка моделей не подтверждает корректную
работу редактирования файлов или всех инструментов модели.

Старый `source="opencode"` не преобразуется в Pi автоматически. Выбери доступное
подключение Pi явно. История OpenCode остаётся историей другой среды.

## Задание Чифу

В консоли `start.cmd` напиши задачу обычным текстом. Можно заранее сохранить
подробности в `TASK.md` и попросить Чифа прочитать файл. При расхождении файла
и текущего сообщения действуют текущие указания пользователя.

Например:

> Прочитай TASK.md. Сначала опиши план и договорённости между частями программы.
> Затем подготовь заготовки и тесты, поручи реализацию исполнителям и проверь результат.

Для одного сообщения из терминала:

```powershell
.\start.cmd --prompt "Прочитай TASK.md и начни работу по правилам кита"
```

Это настоящий запрос к выбранной модели. Он может расходовать оплачиваемые
токены. Установка и подготовка настроек сами такое сообщение не отправляют.

Кит запускает Чифа через свою службу Pi RPC. Это консоль кита;
самостоятельный Pi TUI не управляет этими сессиями автоматически.

## Пауза, продолжение и закрытие

| Действие | Результат |
| --- | --- |
| `/sessions` | Показать сессии проекта и их состояние |
| `/pause` или пауза в дашборде | Приостановить всю текущую задачу, включая исполнителей |
| `/resume` или продолжение в дашборде | Продолжить текущую задачу с проверкой подготовленных настроек |
| `/cancel` или остановка в дашборде | Остановить текущую задачу; это не приёмка результата |
| `/quit` | Закрыть консоль; служба продолжает работать |
| `start.cmd --stop-service` | Безопасно закрыть службу проекта |

Закрытие окна браузера не останавливает агентов. Для паузы используй команду
или кнопку и дождись подтверждения. Отсутствие вывода в консоли не означает,
что все исполнители уже остановлены.

Чтобы сменить модели во время работы:

1. Приостанови задачу и дождись подтверждения остановки её сессий.
2. Запусти `start.cmd --configure`.
3. Измени модели, сохрани и подготовь настройки.
4. Продолжи задачу из дашборда или консоли.

![Пауза и смена настроек](../../readme_gif/pi_sessions.gif)

Если служба была остановлена или компьютер выключился, сохранённые записи
позволяют восстановить разговор. Новое продолжение использует историю;
оно не восстанавливает оборванный сетевой запрос с прежнего места.

Обычный запуск `start.cmd` создаёт новую задачу. Чтобы открыть прежний разговор,
используй точный идентификатор из строки `Session:` первоначального запуска
или из `/sessions`:

```powershell
.\start.cmd --session pi_идентификатор_вашей_сессии
```

Это обозначение места для своего идентификатора, а не готовый ID. После открытия
приостановленной задачи введи `/resume`. Пока Чиф выполняет запрос, консоль
читает его ответ; для срочной паузы нажми `Ctrl+C` или используй дашборд.

## Что хранится рядом с проектом

| Путь | Содержимое |
| --- | --- |
| `.tools/pi/` в шаблоне | Общая локальная установка Pi |
| `.tools/npm-cache/` в шаблоне | Кеш установки пакетов |
| `.pi/installation.json` в целевом проекте | Путь к локальной установке шаблона |
| `.pi/kit-models.json` | Сохранённый выбор пользователя |
| `.pi/kit-runtime.json` | Подготовленные роли и пути для службы |
| `.pi/agent/` | Подготовленные настройки и модели Pi |
| `.pi/agent/auth.json` | Локальные учётные данные встроенных провайдеров Pi |
| `.pi/kit-service/registry.json` | Реестр сессий, родителей и процессов |
| `.pi/kit-service/sessions/` | Сохранённые разговоры Pi |
| `.pi/kit-service/connection.json` | Локальное подключение к службе с её токеном |
| `.metrics/` | Журнал, попытки, рабочие копии и отчёты кита |

Подкаталоги службы и история описаны в [карте адаптеров](../kit/PI_ADAPTERS.ru.md).
Эти данные относятся к конкретному компьютеру; их не нужно публиковать вместе
с исходным кодом. Ключи хранятся отдельно от проекта.

Если после сохранения ключа уже работающая служба его не видит, останови её
и запусти заново. Окружение процесса формируется при его запуске.

Для повторной подготовки без отправки задачи:

```powershell
.\start.cmd --prepare-only
```

Текущий объём проверенного поведения указан в
[PI_VALIDATION.ru.md](../kit/PI_VALIDATION.ru.md). Числа тестов исходной версии
OpenCode не следует считать результатами адаптации.
