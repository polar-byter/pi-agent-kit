# Использование загруженной модели LM Studio

Ты загружаешь модель в LM Studio и выбираешь её параметры: размер контекста, распределение по GPU и остальные настройки. Кит использует эту загрузку. Он не вызывает Load или Unload и не отправляет параметры загрузки.

## Обычный запуск

Включи сервер LM Studio и загрузи нужную модель. В терминале проекта запусти:

```powershell
kit\python.cmd kit/run_opencode.py
```

Скрипт выберет загруженную модель и откроет OpenCode. Дальше описываешь задачу обычным текстом. Мастер Чиф сам ведёт план, делегирование, проверки и статистику.

Прямой запуск задачи из терминала тоже поддерживается:

```powershell
kit\python.cmd kit/run_opencode.py -- run "Описание задачи"
```

Для `run` скрипт по умолчанию использует `--standalone`, чтобы новый процесс прочитал текущие настройки. Остальные аргументы после `--` передаются OpenCode.

У отдельного сервера свой поток событий. Открытое окно desktop, подключённое к фоновому сервису, не показывает его работу вживую. Если хочешь следить за задачей в desktop, подготовь модель через `--prepare-only --reload`, открой проект в desktop и запускай задачу там. Режим `run` в загрузчике пока не переключён на общий сервер по умолчанию.

## Если OpenCode уже открыт

Мастер Чиф перед первым обращением к исполнителю выполняет:

```powershell
kit\python.cmd kit/run_opencode.py --prepare-only --reload
```

Скрипт записывает выбор и вызывает `opencode reload` для фонового сервиса. Для отдельно запущенного `--standalone` процесса это не обновляет его частный сервер: такой процесс запускай через наш скрипт с самого начала. Если проект открывается в другом экземпляре OpenCode, подготовь выбор через `--prepare-only` и открой проект заново.

## Как выбирается модель

1. Скрипт читает `/api/v1/models` LM Studio. В отличие от общего списка `/v1/models`, поле `loaded_instances` позволяет определить уже загруженные экземпляры.
2. Embedding-модели пропускаются: они предназначены для поиска и векторов, а не написания кода.
3. Если загружен один экземпляр языковой модели, используется он — даже когда в исходном конфиге указана другая модель.
4. Если экземпляров несколько, предпочтение получает модель из настройки `executor`, но только если она загружена и выбор однозначен.
5. Если выбрать однозначно нельзя, скрипт показывает ID загруженных экземпляров. Выбери один:

```powershell
kit\python.cmd kit/run_opencode.py --model "ID загруженного экземпляра"
```

Указание незагруженной модели через `--model` — ошибка. Скрипт не заменяет её другой моделью и не запускает OpenCode. Если моделей нет, нужно загрузить одну в LM Studio.

## Что меняется в проекте

Выбор записывается в `.opencode/opencode.jsonc`. OpenCode объединяет этот файл с исходным `opencode.jsonc`. Локальный файл меняет только модель у `executor` и `executor-fast` и добавляет алиас `loaded-executor` с ID выбранного экземпляра. Мастер Чиф, инструкции и права исполнителей остаются прежними. Оба исполнителя используют одну загруженную модель; слово `fast` здесь обозначает роль, а не другую маленькую модель.

Исходный конфиг с комментариями не переписывается. В самом ките локальный файл исключён из Git. В проекте, куда копируешь кит, добавь в `.gitignore`:

```gitignore
.opencode/opencode.jsonc
.opencode/opencode.jsonc.tmp
.opencode/kit-models.json
```

Если у тебя уже есть собственный `.opencode/opencode.json` или `.opencode/opencode.jsonc`, скрипт остановится и сохранит его. Сначала перенеси его настройки в исходный конфиг проекта. Файл с нашей служебной первой строкой считается созданным скриптом и обновляется при следующем запуске.

## Другой Мастер Чиф или исполнители: модель OpenCode или свой API

Новый шаблон использует DeepSeek V4.1 Flash Free из OpenCode для Чифа и Bug Fixer,
MiMo V2.6 Flash Free для исполнителей. LM Studio остаётся отдельным доступным
источником; старый конфиг с локальными моделями сохраняет свой порядок запуска.
Необязательный `.opencode/kit-models.json` записывается конфигуратором и выбирает
модели для конкретной папки. В нём также могут быть отдельный `bugFixer` и лимиты
`execution`. Понятная схема: [руководство](../kit/EXECUTION_GUIDE.ru.md).

### Через окно настроек

При первом открытии конфигуратор выбирает поддерживаемый язык системы (EN/RU),
иначе English. Переключатель **Language** справа вверху задаёт ручной выбор.
Выбор сохраняется отдельно для этого проекта в `.metrics/.configurator-ui.json`.
Его использует и дашборд; без сохранённого выбора дашборд берёт язык браузера.
Переключение не меняет модели, ключи и черновик формы. Описания ниже используют
русские подписи; английские: Master Chief, Executors, Own API, Save settings.

В дашборде нажми кнопку настроек моделей. В окне «Модели проекта» выбери
крупную кнопку **Master Chief** или **Executors** (русские подписи при выбранном
Russian — «Мастер Чиф» и «Исполнители»), затем вариант **Own API** / «Свой API».
Выбранный раздел выделен синим, под названием кнопки есть пояснение.

1. Укажи базовый адрес OpenAI-совместимого API, например `https://api.example.com/v1`.
   Не добавляй `/chat/completions`, `/responses` или `/models`.
2. Вставь API-ключ. Если окно пишет, что ключ уже сохранён, можно оставить поле пустым.
   Имя переменной выбрано автоматически; менять его можно в «Дополнительно».
3. Нажми **«Получить модели»** и выбери модель либо введи её точное имя вручную.
   Кнопка проверяет только получение `/models`, без генерации и проверки инструментов.
4. Нажми **«Сохранить настройки»**. Выбор используется при следующем запуске через кит.
   Текущая сессия сама не переключается.

Кнопка **«Подготовить OpenCode»** сначала сохраняет выбор, затем собирает надстройку
через существующий `--prepare-only`, без перезапуска текущей сессии. Получение списка
и подготовка выполняются в фоне. При ошибке поля остаются заполненными.
**«Вернуть по умолчанию»** сбрасывает файл выбора, но оставляет ключи Windows.

Для разработки и проверки окна отдельно: `kit\python.cmd -m kit.configurator.app`.
Этот способ запуска не требуется пользователю дашборда.

### Витрина OpenRouter

Открой раздел кнопкой **OpenRouter — Model catalog & prices**
(по-русски — **OpenRouter — Каталог и цены**).
Публичный каталог загружается автоматически; API-ключ для просмотра не нужен.
Над таблицей выбери **«Исполнители»** или
**«Мастер Чиф»**, затем щёлкни по строке модели. Для этой роли будут заполнены
вариант «Свой API», адрес `https://openrouter.ai/api/v1` и точный ID модели.
У бесплатной версии сохраняется окончание `:free`.

Нажми **«К настройкам роли»**, вставь ключ OpenRouter при необходимости и сохрани
настройки. По умолчанию используется общая переменная `OPENROUTER_API_KEY`:
один введённый ключ можно использовать для двух ролей. Ключ другого API при
переходе на OpenRouter не переносится. Выбор строки ничего не записывает на диск.

В таблице отдельно показаны вход и выход в USD за **1 млн токенов**, контекст,
тариф и заявленная поддержка инструментов. «Условный» означает наличие особых
ставок у модели; дополнительные цены кэша/запроса показаны под выбранной строкой.
Неизвестная цена обозначается «—». Это ставки каталога, не расчёт будущего счёта.

Есть поиск, бесплатные/платные, сортировка и переключатель «Все текстовые».
«Для кода» объединяет категорию programming OpenRouter с моделями, в названии
или описании которых упомянута работа с кодом; это не доказанный рейтинг качества.
По умолчанию включён фильтр поддержки инструментов, необходимой агентам.
**«Обновить цены»** получает свежие данные; без интернета остаётся предыдущий
каталог с пометкой. Наличие модели в каталоге не проверяет доступность генерации.

Источник формата и единиц цен: [OpenRouter Models API](https://openrouter.ai/docs/guides/overview/models).

| Файл выбора | Мастер Чиф (`build`, `plan`) | Исполнители |
| --- | --- | --- |
| Нет файла | Модель из `opencode.jsonc` | Загруженная модель LM Studio, как описано выше |
| `"masterChief": {"source": "opencode", "model": "openai/gpt-6.1-sol"}` | Указанная модель, которую OpenCode уже знает: OpenCode Go, подписка ChatGPT через `/connect` и другие | — |
| `"executors": {"source": "opencode", "model": "openrouter/…:free"}` | — | Указанная модель, которую OpenCode уже знает, например бесплатная модель OpenRouter, подключённого через `/connect`. LM Studio не опрашивается |
| `"masterChief"` или `"executors"` с `"source": "api"` | Свой API, совместимый с OpenAI | Свой API; LM Studio не опрашивается |
| `"executors": {"source": "lmstudio", "instance": "ID"}` | — | Указанный загруженный экземпляр, если загружено несколько. `--model` в командной строке важнее |

Пример:

```json
{
  "masterChief": {
    "source": "api",
    "baseURL": "https://api.example.com/v1",
    "model": "some-model",
    "keyEnv": "OCK_MASTER_CHIEF_API_KEY"
  },
  "executors": { "source": "lmstudio" }
}
```

В файле хранится только **имя** переменной окружения с ключом (`keyEnv`), сам ключ — в переменных Windows. Если переменная не задана, скрипт остановится и ничего не изменит. После сохранения ключа открой новый терминал, чтобы он увидел переменную.

Скрипт этот файл только читает. Удалил файл — при следующем запуске всё вернулось к поведению по умолчанию. Агентам скрипт сообщает, откуда исполнители: `OPENCODE_KIT_EXECUTORS` равна `lmstudio`, `opencode` или `api`.

## Что нужно учитывать

При запуске отдельного сервера загрузчик передаёт агенту путь проекта, ID выбранного экземпляра и тип сервера через переменные `OPENCODE_KIT_ROOT`, `OPENCODE_KIT_INSTANCE`, `OPENCODE_KIT_SERVER_MODE`. Это сведения об окружении, а не план задачи. Агент проверяет соединение, но не перезагружает фоновый OpenCode: его перезагрузка не влияет на отдельный сервер и может затронуть другой открытый проект.

Не выгружай и не меняй выбранную модель во время задачи. Выбор делается перед запуском, а не перед каждым токеном. Если LM Studio сам выгрузит экземпляр по таймеру, его дальнейшее поведение зависит от настроек автоматической загрузки LM Studio. Скрипт эти настройки не меняет. После смены модели запусти подготовку заново.

`check_env.py` и `pipeline_smoke.py` используют тот же выбор загруженных моделей. Они больше не берут первую скачанную модель. Проверка среды посылает короткий пробный запрос; smoke-проверка просит реализовать небольшой пример. При неоднозначном выборе они тоже принимают `--model`.

Проверено на OpenCode 2.0.21: загрузка локального конфига, сохранение прав `shell: deny`, ответ локального `executor-fast` и настоящий вызов исполнителя Мастер Чифом. После обновления OpenCode повтори эти проверки: важно проверить не только синтаксис конфига, но и модель в экспортированной сессии исполнителя.

Описание API: [загруженные экземпляры LM Studio](https://lmstudio.ai/docs/developer/rest/list). Порядок объединения файлов: [конфигурация OpenCode V2](https://dev.opencode.ai/v2/docs/config/).
