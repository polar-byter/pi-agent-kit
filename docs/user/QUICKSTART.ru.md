# Быстрый старт: кит для OpenCode, понятно и по шагам

> Инструкция «с нуля» для тех, кто не программирует каждый день.
> English version: [QUICKSTART.en.md](QUICKSTART.en.md) · Обзор проекта: [README.md](../../README.md) ·
> Короткая инструкция по мастеру установки: [OPENCODE_KIT.ru.md](OPENCODE_KIT.ru.md)

Здесь по шагам описано, как установить кит, выбрать модели и поставить первую
задачу. Восемь анимированных схем показывают каждый этап; данные в них примерные.
Пример ручного подключения — небольшое приложение на Java, но порядок одинаков
для любого языка.

---

## 1. Что это и зачем

Представь стройку. Есть **прораб**, который читает задание, чертит план, раздаёт
работу и принимает результат. Есть **рабочие**, которые делают небольшие участки
строго по чертежу, и несколько рабочих могут трудиться одновременно. Если участок
не получился, его переделывает **другой мастер**.

В ките так же:

- 🪖 **Мастер Чиф** — главный ИИ-агент (в OpenCode он называется `build`). Разбирается
  в задаче, придумывает устройство программы и договорённости между её частями,
  пишет «скелет» кода с подробными пояснениями и тесты, проверяет работу и в конце
  проверяет интерфейс приложения.
- 🛠 **Исполнители** — модели, которые заполняют «внутренности» функций по готовому
  описанию. Их может быть от одного до восьми; каждый работает в своей копии файлов.
- 🩹 **Исправитель ошибок** (Bug Fixer) — отдельная модель со своим запасом
  исправлений, если исполнитель ошибся или упёрся в лимит.
- ⚙ **Контроллер** — не ИИ, а обычная программа кита: раздаёт копии файлов,
  следит за лимитами и переносит принятый код в проект.
- 📒 **Журнал и дашборд** — скрипт учёта записывает каждый шаг, а страница
  в браузере показывает, что сейчас происходит.

Твоя роль — сказать, что нужно сделать, ответить на вопросы и принять результат.
Команды, проверки и статистику Мастер Чиф выполняет сам.

![Кто в команде](../../readme_gif/02_team.gif)

### Как Мастер Чиф готовит работу

Получив задачу, Мастер Чиф сначала читает документы проекта: требования (твоё
сообщение или файл `TASK.md`), правила кита (`AGENTS.md`), план прошлых сессий
(`currentsteps.md`) и описание того, что уже есть в коде. Затем решает, из каких
частей будет программа и в каком порядке их делать, и записывает договорённости
между частями: какие функции есть, что принимают и возвращают. Для каждой части
он создаёт заготовку — названия функций и подробное описание. Сразу же пишет тесты:
маленькие автоматические проверки. Пока функции пустые, тесты не проходят
(«красные»), пока работа не выполнена.

![Как Мастер Чиф готовит работу](../../readme_gif/03_plan.gif)

### Как работают исполнители

Если части программы не зависят друг от друга, их можно делать одновременно.
Контроллер даёт каждому исполнителю свою копию файлов — основной проект они не
трогают. За каждой попыткой следит сторож: сколько шагов, сколько времени, не
повторяет ли модель одно и то же. Мастер Чиф проверяет каждую копию отдельно:
что изменилось, проходят ли её тесты, выполнены ли все требования. Принятые файлы
переносятся в проект по одному, и ничего чужого при этом не перезаписывается.

![Несколько исполнителей одновременно](../../readme_gif/04_parallel.gif)

### Когда зовут исправителя ошибок

Если проверка нашла ошибку или исполнитель исчерпал лимит, работа переходит
исправителю: тот же файл, те же требования и текст ошибок. Ошибка сервиса (например,
лимит запросов `429`), сломанная тестовая среда, пауза или отмена исправителя не
запускают. Когда запас исправлений исчерпан — всё останавливается словом `STOP` и ждёт твоего
решения.

![Исправитель ошибок](../../readme_gif/05_bugfixer.gif)

## 2. Несколько слов, которые встретятся дальше

| Слово | Что значит |
| --- | --- |
| **Модель** | «Мозг» ИИ, который пишет текст и код. Бывают облачные (в интернете) и локальные (на твоём компьютере). |
| **LM Studio** | Программа, которая запускает модель прямо на твоём компьютере. Бесплатно, без интернета, но нужна мощная видеокарта. |
| **OpenRouter** | Сайт-посредник, через который можно подключить сотни облачных моделей, в том числе бесплатные (их имя оканчивается на `:free`). |
| **API и API-ключ** | Адрес сервиса с моделями и «пароль» к нему. Ключ хранится в переменной Windows, а не в файлах проекта. |
| **Тест** | Маленькая программа, которая проверяет, что функция работает правильно. Зелёный — прошёл, красный — нет. |
| **Каркас, заготовка** | Код с названиями и описаниями функций, но без «внутренностей». |
| **Договорённости (контракты)** | Что каждая часть программы обещает другим: функции, их входы и выходы, общие типы, схема базы данных. |
| **Попытка** | Один запуск модели для одного поручения. Возврат на доработку или передача исправителю — новая попытка. |
| **Копия файлов** | Отдельная папка, где исполнитель работает, не трогая основной проект. |
| **Токены** | Кусочки текста, которыми модель читает и пишет. По ним видно, сколько работы сделала каждая модель. |
| **Дашборд** | Страница в браузере, где видно, как идёт задача. Открывается сама. |

## 3. Что нужно установить

| Что | Зачем | Как проверить |
| --- | --- | --- |
| OpenCode Desktop 2.x | приложение, в котором живут агенты | открывается окно OpenCode |
| Python 3.13.16 с Tk | установщик подготовит автоматически при первом запуске | вручную устанавливать не нужно |
| Доступ к моделям | бесплатные модели OpenCode уже выбраны в шаблоне; можно LM Studio, OpenRouter или свой API | см. раздел 6 |
| Инструменты твоего языка | для примера ниже: JDK 21 и Maven | `java -version`, `mvn -v` |

> Python нужен инструментам кита. Его отдельная копия устанавливается в личную папку,
> системные версии сохраняются. Команды ниже используют `kit\python.cmd` на Windows;
> на Ubuntu/Debian/Mint вместо него пиши `sh kit/python.sh`. Обычному пользователю эти
> команды вводить не нужно. macOS пока требует самостоятельной установки Python с Tk.

## 4. Путь А: мастер установки (рекомендуется)

![Установка за четыре шага](../../readme_gif/01_install.gif)

Как это выглядит в самом мастере:

![Мастер установки](../../readme_gif/01_install_live.gif)

1. На [странице репозитория](https://github.com/polar-byter/opencode-environmental-tune)
   нажми **Code → Download ZIP** и полностью распакуй архив в отдельную папку.
2. Дважды щёлкни **install.cmd**. Откроется мастер «Создание проекта».
3. **Шаг 1** — мастер сам находит OpenCode Desktop. Если не нашёл, нажми
   «Скачать OpenCode», установи и затем «Проверить ещё раз».
4. **Шаг 2** — выбери папку для своего приложения или впиши новый путь, например
   `D:\Projects\my-home-app`. Недостающие папки мастер создаст сам. Лучше брать папку
   вне скачанного кита. Если в папке уже есть свой код, конфликтующие настройки кита
   не перезапишутся — мастер объяснит проблему.
5. **Шаг 3** — «Создать проект и настроить модели». Мастер скопирует кит и откроет
   окно настроек моделей. Начальный выбор уже есть: Мастер Чиф и исправитель —
   DeepSeek V4.1 Flash Free, исполнители — MiMo V2.6 Flash Free, один одновременно.
   Нажми «Сохранить настройки», затем «Подготовить OpenCode» и дождись успешного результата.
6. **Шаг 4** — мастер запускает Desktop с просьбой открыть папку проекта. Проверь
   имя проекта в Desktop: если открылся другой, нажми в мастере «Копировать путь»,
   в Desktop выбери **Open Project** и вставь путь.
7. Скопируй пример задания из мастера, при желании измени его под себя, вставь
   в **новый чат build** и отправь. Сам мастер модели ничего не отправляет.

Доступность бесплатных моделей меняется: если модель недоступна, выбери другую
в окне настроек (раздел 6). Подробная инструкция по экранам мастера:
[OPENCODE_KIT.ru.md](OPENCODE_KIT.ru.md).

## 5. Путь Б: подключить кит к своему проекту вручную

Если у тебя уже есть проект и мастер не нужен, кит можно положить руками.
Пример ниже — Java-проект из [start.spring.io](https://start.spring.io)
(Maven, Java 21, зависимости `Spring Web` и `Validation`), распакованный в `D:\PROJECTS\task-api`.

**Скопируй в корень проекта четыре вещи из этого репозитория:**

```
opencode.jsonc        ← какие агенты есть и какие у них права
AGENTS.md             ← правила работы Мастер Чифа
kit/                  ← скрипты кита (учёт, контроллер, дашборд, настройки моделей)
.opencode/commands/   ← необязательные команды /plan-project и /module
```

Добавь в `.gitignore` проекта строки, чтобы личные настройки и журналы не попали в Git:

```gitignore
.opencode/opencode.jsonc
.opencode/opencode.jsonc.tmp
.opencode/kit-models.json
.metrics/
```

**Расскажи киту о проекте в `AGENTS.md`.** Меняются только разделы с пометкой `# EDIT`.

`Project stack` — язык и, главное, команда запуска тестов:

```md
## Project stack  # EDIT: language, build tool, test command
- Language: Java 21 (`java -version`). Build tool: Maven (`mvn`).
- Tests: JUnit 5. Maven writes one JUnit XML file per test class into `target/surefire-reports`.
- Test command (always through task_metrics):
  `kit\python.cmd kit/task_metrics.py test --task <ID> --junit-dir target/surefire-reports -- mvn -q test`
- Compile only: `mvn -q compile`.
- Run the app: `mvn spring-boot:run`.
```

`Project layout` — где лежат код и тесты:

```md
## Project layout  # EDIT: folders and files of this project
- `src/main/java/com/example/taskapi/` — application code.
- `src/test/java/com/example/taskapi/` — tests.
- `pom.xml` — Maven build file.
```

`Work plan (memory)` — имя файла плана, по умолчанию `currentsteps.md`. С Obsidian
план хранится в твоём хранилище, без него — в корне проекта.

Для других языков готовые команды тестов есть в таблице
[«Подключение своего языка»](../../README.md#подключение-своего-языка).

**Проверь, что кит понимает результаты тестов.** Один раз выполни в корне проекта:

```bash
kit\python.cmd kit/task_metrics.py check --junit-dir target/surefire-reports -- mvn -q test
```

- `CHECK OK` — всё в порядке. Упавшие тесты на этом шаге не мешают.
- `CHECK FAILED` — скрипт не может прочитать результат; ниже строки будут подсказки.

Мастер Чиф делает эту проверку и сам перед каждой задачей и не начинает писать код,
пока она не проходит. Окно выбора моделей запускается командой
`kit\python.cmd -m kit.configurator.app` из корня проекта (или попроси Мастер Чифа его открыть).

## 6. Модели, число исполнителей и лимиты

![Модели, лимиты и ключи](../../readme_gif/07_models.gif)

Окно «Модели проекта» открывается из мастера установки, кнопкой **«Настройки моделей»**
в дашборде или по просьбе Мастер Чифу. Вверху четыре раздела: **Мастер Чиф**,
**Исполнители**, **Исправитель ошибок** и **OpenRouter** (каталог с ценами).

**Откуда брать модель** — для каждой роли свой выбор:

| Роль | Варианты источника |
| --- | --- |
| Мастер Чиф | «Из настроек проекта», «Модель из OpenCode», «Свой API» |
| Исполнители | «Локально · LM Studio», «Модель из OpenCode», «Свой API» |
| Исправитель ошибок | «Выключен», «Модель из OpenCode», «Свой API» |

- **Модель из OpenCode** — модели, которые OpenCode уже знает: бесплатные модели
  каталога OpenCode и всё, что подключено командой `/connect` (OpenCode Go, подписка
  ChatGPT, OpenRouter и др.).
- **Локально · LM Studio** — только для исполнителей. Загрузи модель в LM Studio
  (кнопка **Load**) и включи сервер (**Developer → Start Server**). Параметры загрузки
  выбираешь ты: кит никогда сам не загружает и не выгружает модели.
- **Свой API** — любой совместимый с OpenAI сервис: адрес вида `https://api.example.com/v1`
  (без `/chat/completions` и `/models`), ключ и точное имя модели. Кнопка «Получить модели»
  подгружает список.

**Сколько исполнителей и какие лимиты.** В разделе «Исполнители»:

| Поле | По умолчанию | Что значит |
| --- | --- | --- |
| Одновременных исполнителей | 2 | 1 — по очереди; 2–8 — параллельно, но только для независимых частей |
| Шагов на попытку | 24 | сколько действий модель может сделать за одну попытку |
| Секунд на попытку | 600 | сколько времени даётся на одну попытку |
| Ошибок исполнителя на модуль | 3 | отдельный запас исполнителя |
| Ошибок Bug Fixer на модуль | 6 | дополнительные исправления остаются у Bug Fixer |
| Общий предел ошибок кода | 9 | предел на модуль; API и настройка не расходуют этот запас |
| Повторов без прогресса | 3 | сколько одинаковых действий без результата допустимо |

Это максимум: если частей меньше или они зависят друг от друга, исполнителей работает меньше. Часть, которая
зависит от ещё не принятой другой части, ждёт своей очереди. Лимиты аккаунта у
провайдера общие на всех исполнителей.

**Исправитель ошибок** — свой источник и свои лимиты (по умолчанию 32 шага и 600 секунд).
Если выбрать «Выключен», исправителя не будет.

**Каталог OpenRouter.** Список моделей загружается без ключа; цены — в долларах за
1 млн токенов, отдельно за вход и выход. Включи фильтры «Для кода», «Только с
инструментами» (без них агент не сможет работать) и при желании «Бесплатные».
В поле «Подставить в:» выбери роль и щёлкни строку: роль получит вариант «Свой API»,
адрес `https://openrouter.ai/api/v1` и точное имя модели. Щелчок ещё ничего не сохраняет.

**Ключи.** Ключ хранится в переменной пользователя Windows, в проекте — только её имя.
Если ключ уже сохранён, окно пишет **«Ключ найден»** — вводить его снова не нужно.
Один `OPENROUTER_API_KEY` подходит всем ролям. Кнопка **«Проверить связь»** показывает,
отвечает ли сервис; генерация при этом не запускается и ничего не сохраняется.

**Сохранить и применить.** «Сохранить настройки» записывает выбор в `.opencode/kit-models.json`
этой папки. «Подготовить OpenCode» собирает файл-надстройку `.opencode/opencode.jsonc`.
Текущий чат на новые модели не переключается — открой **новый чат build**. Если только
что добавил новый ключ, полностью перезапусти OpenCode Desktop.

> Параллельная работа и сторож лимитов работают в общей службе OpenCode Desktop.
> Если запустить OpenCode отдельно (`kit\python.cmd kit/run_opencode.py` в частном режиме
> `--standalone`), кит работает по прежнему последовательному протоколу.

Подробнее: [руководство конфигуратора](../../kit/configurator/UX.ru.md),
[LOCAL_MODELS.ru.md](LOCAL_MODELS.ru.md), [устройство исполнителей и метрик](../kit/EXECUTION_GUIDE.ru.md).

## 7. Поставить задачу

Открой папку проекта в OpenCode и создай новый чат **build**. Дальше есть два
равноправных способа:

**Способ А — прямо в чате.** Просто опиши, что нужно:

```text
Создай локальное приложение для домашних дел и расписания дня.
Нужны список дел с датами и статусами и таблица дня: время начала,
время окончания, занятие. Данные храни в SQLite. Интерфейс — на русском,
с понятными подписями. Следуй правилам кита, составь план, подготовь тесты,
поручай реализацию исполнителям и выполни весь план. В конце проверь
интерфейс и подготовь файл запуска.
```

**Способ Б — через файл `TASK.md`.** Опиши требования и критерии приёмки в `TASK.md`
в корне проекта, сохрани файл и напиши в чат одно слово: **«Начинай»**.

Несколько правил:

- Если в чате и в файле написано разное, главнее сообщение в чате.
- Мастер Чиф не перезаписывает `TASK.md` без твоей просьбы.
- Перечислять ему документы не нужно: `AGENTS.md`, план и README он найдёт сам.
- Само открытие папки работу не запускает — нужен запрос в чате.

Мастер Чиф откроет учёт задачи и сам запустит дашборд в браузере, затем покажет план:
на какие части делится задача и в каком порядке их делать. Проверь, что план
соответствует задаче, и ответь, например: «План подходит. Реализуй его целиком,
проверь результат и покажи статистику».

## 8. Наблюдать за работой в дашборде

![Дашборд](../../readme_gif/08_dashboard.gif)

Пока ты занимаешься своими делами, дашборд показывает:

- **Сейчас в работе** — каждый участник: какой исполнитель или исправитель над какой
  функцией работает, сколько готово, сколько токенов и времени ушло.
- **Обзор** — статус задачи, возвраты на доработку, прогоны тестов, сбои исполнителя,
  последние события. Обновляется каждые 2 секунды.
- **Детализация работ** — все попытки по каждому заданию: кто делал, чем закончилось,
  перенесены ли изменения в проект.
- **Токены** — расход по моделям и отдельно по каждой попытке. Если у части сообщений
  нет данных, сумма помечается «≥», а ноль не подставляется.

Язык страницы — как в браузере (русский или английский); переключатель **«Язык»**
запоминает выбор для проекта.

Кнопки управления задачей:

| Кнопка | Что происходит |
| --- | --- |
| **⏸ Приостановить** | Мастер Чиф и все исполнители останавливаются. Код, план и история сохраняются. Новые действия по задаче запрещены, пока не продолжишь. |
| **▶ Продолжить** | Мастер Чиф получает просьбу продолжить ту же задачу: перечитать план и проверить то, что успели сделать до паузы. Защитные лимиты не сбрасываются. |
| **■ Остановить** | Задача отменяется, очереди сообщений очищаются. Это не «успешное завершение». |
| **Удалить задачу…** | После подтверждения удаляются сессии и журнал этой задачи. Код приложения остаётся. |
| **Настройки моделей** | Открывает окно выбора моделей. Ничего не применяется само — выбор действует для следующей задачи. |

Подробности и ограничения: [управление задачами](../../kit/dashboard/CONTROLS.ru.md).

## 9. Что делает Мастер Чиф после согласования плана

Дальше всё идёт само, по частям:

1. Создаёт **каркас** функции с описанием и заглушкой, например:
   ```java
   public Task create(String title) {
       throw new UnsupportedOperationException("TODO: executor");
   }
   ```
2. Пишет **тесты** и запускает их — пока они не проходят.
3. Поручает **исполнителю** небольшой класс целиком. Если выбрано больше одного
   исполнителя и части не зависят друг от друга, поручает их параллельно — каждую
   в своей копии файлов.
4. Исполнитель заполняет **только тела функций**; сторож следит за его шагами и временем.
5. Мастер Чиф проверяет, не тронуто ли лишнее, сверяет требования с кодом и запускает
   тесты именно этой копии. Ошибка — возврат; после ошибки кода или лимита — одна
   попытка исправителя. Проблема со сборкой или настройкой — Мастер Чиф чинит сам или
   спрашивает тебя.
6. Принятый файл переносится в основной проект, часть отмечается в плане, Мастер Чиф
   берёт следующую.
7. Сработала защита (`STOP`) — объясняет причину и ждёт твоего решения: уточнить
   задание, поправить тесты, настройку или модель.

Он обращается к тебе, только если не хватает доступа, инструментов или нужно решение,
меняющее задачу. Переходы между частями согласовывать не нужно.

## 10. Получить результат

![Финал](../../readme_gif/06_final.gif)

Когда все части приняты и перенесены, начинается этап улучшения UI/UX. Мастер Чиф
запускает приложение и проходит обычные сценарии: открывает формы, заполняет,
сохраняет, проверяет сообщения об ошибках. Отмечает, что неудобно, и правит интерфейс —
логика и договорённости не меняются. Итог этапа записывается в журнал: без этой записи
задачу завершить нельзя. В отчёте будет «Этап улучшения UI/UX выполнен…», «…пропущен
ввиду …» (например, когда нет браузера) или «…не требуется» (у приложения нет интерфейса).

Затем обязательно запускает **все** тесты проекта и показывает итог и статистику:

- сколько длилась задача;
- токены платных моделей, локальных (LM Studio) и бесплатных облачных
  (`:free` у OpenRouter, `-free` у OpenCode);
- расход по каждой попытке исполнителя и исправителя — входит в общий итог;
- сколько раз работу возвращали на доработку и сколько прогонов тестов прошло.

В дашборде появится блок **«✓ Работа завершена»** с кнопками: открыть папку проекта,
посмотреть файл запуска и итоговый отчёт.

Чтобы проверить приложение в деле, напиши:

```text
Запусти приложение и проверь основные сценарии. Покажи результат
проверки и как остановить приложение.
```

## 12. Частые проблемы

| Что видишь | Почему | Что делать |
| --- | --- | --- |
| Подготовка Python не завершилась | Нет интернета, места или загрузка повреждена | Проверь причину в окне запуска и повтори установку; другую версию Python вручную ставить не нужно |
| Desktop открыл не ту папку | Не все версии Desktop выбирают папку по ссылке | «Копировать путь» в мастере → **Open Project** в Desktop |
| Выбранная модель недоступна | Бесплатные модели и лимиты меняются | Выбери другую модель в окне настроек, «Подготовить OpenCode», новый чат |
| Работа стоит, в отчёте лимит запросов / `429` | Лимит провайдера (у бесплатных моделей OpenRouter — дневной) | Подожди или выбери другую модель; исправитель в таком случае не запускается |
| Исполнители не работают параллельно | Выбран 1 исполнитель, части зависят друг от друга или OpenCode запущен в частном режиме | Проверь число в настройках; параллельность работает в общей службе Desktop |
| `Result: test failed` в `check_env` | LM Studio не запущен или модель не загружена | Developer → Start Server; нажать Load у модели |
| Нет «Ключ найден», хотя ключ сохраняли | OpenCode/окно запущены до сохранения ключа | Перезапусти OpenCode Desktop и заново открой окно настроек |
| Модель в чате осталась старой | Текущий чат не переключается | «Подготовить OpenCode», затем новый чат build |
| Команд `/module` не видно | `.opencode/` не скопирован или OpenCode открыт не в корне проекта | Проверь папку проекта |
| OpenCode отклоняет `providers`/`agents` | Запускается старый OpenCode из PATH | См. [какой OpenCode использует кит](../../README.md#какой-opencode-использует-кит) |
| Тесты не компилируются | В каркасе нет импорта (исполнитель их не добавляет) | Скажи Мастер Чифу: «добавь недостающий импорт в каркас» |
| `CHECK FAILED` | Скрипт не может прочитать результат тестов | Прочитай подсказки, проверь команду тестов в `AGENTS.md` |
| Мастер Чиф пишет `STOP` и ждёт | Сработала защита от зацикливания или исправитель не справился | Прочитай причину, реши, что делать, и скажи продолжать |
| Мастер Чиф всё делает сам | Он не видит `AGENTS.md` | Проверь, что `AGENTS.md` лежит в корне проекта |
