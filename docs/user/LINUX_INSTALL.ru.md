# Установка мышкой: Ubuntu, Debian, Linux Mint

1. Получите пакет **opencode-kit_0.2.0_all.deb**. Сборка доступна в GitHub Actions:
   **Linux installer → последний успешный запуск → opencode-kit-linux-deb**.
   Распакуйте скачанный архив артефакта; внутри находится `.deb`.
2. Откройте скачанный файл двойным щелчком. Если открылся архиватор, выберите
   правой кнопкой **Открыть с помощью → Установка программ** / системный менеджер пакетов.
3. Нажмите **Установить**. Система может запросить пароль администратора и интернет
   для установки библиотек Tk и средств подготовки Python. Вводить команды и отдельно
   устанавливать Python не нужно.
4. Откройте меню приложений и найдите **OpenCode Kit — новый проект** (или **OpenCode Kit**).
   При первом запуске появится окно подготовки **Python 3.13.16**. Нужен интернет и
   место для сборки; дождитесь завершения, это занимает несколько минут.
5. В мастере установите OpenCode Desktop по кнопке **Скачать OpenCode**, если он ещё
   не найден. Для Linux выбирайте пакет Desktop для своего дистрибутива, а не только CLI.
   Затем нажмите **Проверить снова**; для нестандартной установки есть **Выбрать приложение…**.
6. Выберите папку проекта или впишите новый путь, например `/home/alex/Projects/home`.
   Отсутствующие папки мастер создаст сам. Папка должна быть доступна вашему пользователю.
7. Нажмите **Создать проект и настроить модели**, выберите модели и API-ключи,
   сохраните и подготовьте OpenCode. После подготовки мастер отправит запрос открытия
   проекта в Desktop. Если Desktop не выбрал папку, нажмите Open Project и вставьте
   путь кнопкой **Копировать путь к папке**.

Мастер запускается от обычного пользователя, без `sudo`. Системный пакет устанавливается
один раз, а проекты создаются в личных папках. Удаление OpenCode Kit через менеджер
программ удаляет мастер, но сохраняет созданные проекты и личные настройки.

API-ключи на Linux хранятся в `$XDG_CONFIG_HOME/opencode-kit/keys.json`, а если эта
переменная не задана — в `~/.config/opencode-kit/keys.json`. Это обычный файл без
шифрования с правами `600`, в папке с правами `700`: читать его может владелец и root.
Ключи не входят в пакет, проект, Git и журналы метрик. Windows продолжает использовать
пользовательский реестр. Не отправляйте файл ключей другим людям.

Пакет рассчитан на Ubuntu/Debian/Mint x86_64/aarch64 с графическим рабочим столом.
Системный Python не требуется и не заменяется: мастер готовит личную закреплённую
копию. `.deb` не является универсальным пакетом для Fedora или Arch. Наличие программы,
которая графически устанавливает локальные `.deb`, зависит от комплектации системы.

## Для разработчика

```mermaid
flowchart LR
    DEB[Пакет .deb] --> MANAGER[Системный менеджер: библиотеки и компилятор]
    MANAGER --> MENU[Меню приложений: opencode-kit.desktop]
    MENU --> ENTRY[/usr/bin/opencode-kit-installer]
    ENTRY --> BOOT[install.sh → desktop.sh → bootstrap.sh]
    BOOT --> PIN[Личный Python 3.13.16 с Tk]
    PIN --> PY[/usr/share/opencode-kit/install.py]
    PY --> WIZARD[InstallerWindow: папка, модели, Desktop]
    WIZARD --> KEYS[keys.py → posix_keys.py: личный файл ключей]
```

**Пакет** — архив файлов с описанием зависимостей, который устанавливает система.
**Зависимость** — программа, необходимая мастеру: Python выполняет код, Tk рисует окно.
**Desktop entry** — файл `.desktop`, добавляющий программу в меню. **Architecture: all**
значит, что пакет содержит сценарии, а не процессорный машинный код. Bootstrap
собирает закреплённый Python для процессора пользователя из официального архива;
это [отдельный нативный этап без Python](../kit/PYTHON_RUNTIME.ru.md).

`kit/linux_package.py` → `build()` собирает стандартный Debian ar-архив с
`debian-binary`, `control.tar.gz`, `data.tar.gz`. `archive()` выставляет права,
владельца root и одинаковые времена файлов для воспроизводимой сборки.
`installer.payload()` задаёт разрешённый состав кита: ключи, журналы и настройки
исходного компьютера не включаются. `kit/configurator/posix_keys.py` → `save()`
атомарно заменяет личный файл, `read()` проверяет права и формат перед чтением.

Сборка для сопровождающего (пользователю эта команда не нужна):

```text
sh kit/python.sh -m kit.linux_package --version 0.2.0 --output dist/opencode-kit_0.2.0_all.deb
```

После сборки проверяются формат через `dpkg-deb`, установка пакета и открытие
настоящего окна Tk в Linux с виртуальным дисплеем. Это не заменяет ручную проверку
двойного щелчка в каждом файловом менеджере и открытия проекта настоящим Linux Desktop.
