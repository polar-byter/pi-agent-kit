# Эксперимент из OpenCode Desktop

Пользователь ставит задачу, а Мастер Чиф самостоятельно читает нужные документы,
готовит выбранные модели, открывает учёт и дашборд, делегирует и проверяет результат.

## Два способа поставить задачу

- **В чате:** открой проект и опиши, что нужно сделать. Заполнять TASK.md не требуется.
- **В файле:** заполни TASK.md, сохрани его и напиши «Начинай» в новом чате build.
  Дублировать требования или перечислять Markdown-файлы не нужно.

AGENTS.md задаёт порядок работы. TASK.md подключён через instructions в конфигурации;
при наличии файла агент использует совместимые требования как контекст. Текущее явное
ТЗ в чате имеет приоритет. Устаревшее или пустое ТЗ в файле не блокирует новую задачу
из чата. Без отдельной просьбы агент не перезаписывает TASK.md описанием из сообщения.

Остальные документы агент находит и читает сам: применимые AGENTS.md, выбранный
currentsteps.md, README и существующую архитектуру, затем нужные инструкции
подготовки, статистики и дашборда. Он читает относящиеся к работе разделы по мере
необходимости. Это часть правил кита, а не обязанность пользователя.

Чтение документов задаёт контекст. Само открытие папки или сохранение Markdown
пока не запускает работу модели: нужен запрос в чате.

## Подготовленная папка эксперимента

Отдельная папка продукта `budget_home` рядом с репозиторием кита.

Старый эксперимент удалён по просьбе пользователя вместе с четырьмя сессиями
его основной семьи. В новой папке кит, выбор моделей и заполненный TASK.md:
домашний бюджет, покупки по продуктам, домашние остатки, графики расходов и
недельный распорядок с причинами невыполнения. Новое приложение ещё не начато.
Свой currentsteps.md хранится в корне этой папки; агент эксперимента не записывает
план в общий Vault или исходный репозиторий кита.

1. Открой эту папку в OpenCode Desktop, создай новый чат build.
2. Поставь задачу любым из двух способов выше.
3. Следи за чатом и дашбордом по ссылке, которую даст агент после начала учёта.

Выполнение идёт в текущем чате Desktop. Отдельный CLI run/standalone не нужен.
Подготовка конфигурации, скрипты статистики и открытие дашборда — действия агента.
Настройки открываются кнопкой Settings. Свой API и выбор OpenRouter описаны
в [руководстве конфигуратора](../../kit/configurator/UX.ru.md). Изменение модели
не переключает существующий чат; после подготовки создай новый чат проекта.

Выбор моделей и адрес API сохраняются для открытой папки в
`.opencode/kit-models.json`. Ключ хранится в пользовательской переменной Windows;
несколько папок могут обращаться к одному имени переменной. Ключи в проект не копируются.

Если ключ уже есть, форма показывает **Key found / Ключ найден** и имя переменной;
повторно вводить его не нужно. **Check connection / Проверить связь** проверяет
выбранное подключение без генерации и сохранения формы. После обновления кита
переоткрой окно настроек, чтобы увидеть новые элементы.

В дашборде выбери нужную задачу и используй «Приостановить», «Продолжить»,
«Остановить», «Удалить задачу». Пауза сохраняет историю и код, остановка отменяет
очередь, удаление очищает семью сессий и метрики. Исходники приложения сохраняются.
Продолжение требует проверки частично сделанной работы и использует прежний task ID.
Правила и ограничения: [управление задачами](../../kit/dashboard/CONTROLS.ru.md).

## Что проверяем

В дашборде должны появиться архитектура, фактические модели, текущая работа,
заявленный/принятый прогресс функций, детализация работ, тесты и доступные токены.
В конце нужны принятое ревью, полный набор тестов, проверка критериев приёмки,
сообщение завершения, папка и файл запуска. Отсутствующие сведения остаются неизвестными.

Для нового опыта перенесён выбор исполнителя Qwen из старого проекта; генерация
через него при подготовке не проверялась. Poolside в более ранней пробе вернул 429.
При недоступном исполнителе агент объясняет причину и останавливается; другую модель
выбирает пользователь. Каталог моделей не заменяет авторизацию и проверку генерации.

Для нового проекта на другом компьютере агент копирует opencode.jsonc, AGENTS.md,
kit/ и .opencode/commands/, настраивает Project stack и Work plan под новый продукт.
TASK.md добавляется только при выборе файлового способа. Исходники и журналы старого
приложения не переносятся; выбор моделей переносится отдельно без ключей.
