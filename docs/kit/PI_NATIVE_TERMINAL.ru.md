# Штатный интерфейс Pi и управление китом

Обновление 18–19 октября 2026 года заменяет основной консольный вход.
`start.cmd` открывает официальный `InteractiveMode` установленного Pi 1.3.0.
Пользователь пишет ТЗ в обычном многострочном редакторе Pi. Файл с ТЗ необязателен.

## Путь запуска

`start.cmd` → kit.run_pi → kit.pi_native.launch_native_pi →
kit/pi/native_chief.mjs → официальный SDK Pi и InteractiveMode.

Python подготавливает выбранные модели и локальную службу, затем передаёт
терминал Node-процессу с Pi. Код кита не рисует редактор и не заменяет его циклом input.
Прежний RPC-вход для сценариев без UI сохранён под явным флагом --headless.
Штатный интерфейс открывается через start.cmd проекта; глобальный запуск отдельного
pi без этого входа не регистрирует управляемую сессию в службе кита.

## Кто владеет историей

Нативный Pi владеет своим AgentSession и пишет единственный файл истории.
Служба регистрирует существующую сессию через session.attachInteractive.
Она сверяет папку истории, идентичность процесса и подтверждение самого Pi.
Повторное подключение того же процесса сохраняет прежний журнал задачи.
Второй процесс для записи в ту же историю не запускается.

Рядом с интерфейсом работает локальный управляющий endpoint с отдельным токеном.
Он слушает только 127.0.0.1. Дашборд и контроллер продолжают обращаться
к той же службе проекта. Исполнители остаются изолированными RPC-процессами.

## Файлы для изучения

| Файл | Ответственность |
| --- | --- |
| kit/pi_native.py | Подготовка и запуск штатного интерфейса с унаследованным терминалом |
| kit/pi/native_chief.mjs | Создание сессии официальным SDK и подключение InteractiveMode |
| kit/pi/native_chief_control.mjs | Управление той же сессией: очередь, остановка, модель, экспорт |
| kit/pi/native_chief_extension.mjs | Проверки допуска, привязка задачи, команды и события Pi |
| kit/runtimes/pi_interactive.py | Адаптер управляющего endpoint к существующему интерфейсу процесса |
| kit/runtimes/pi_native_state.py | Привязка нативного разговора к общему журналу и TaskControls |
| kit/pi_project_update.py | Обновление только проверенных файлов кита в установленном проекте |

Метаданные задачи передаются системным контекстом. Пользовательский текст
остаётся его сообщением в чате. Выбранная модель Чифа проверяется; изменение
через отдельный выбор Pi не подменяет подготовленную конфигурацию трёх ролей.

## Пауза, продолжение и история

Остановка очищает очередь через AgentSession.clearQueue и вызывает abort
того же AgentSession. Продолжение поступает в ту же сессию. Подтверждение
завершения остаётся отдельным фактом: idle Pi не означает finish задачи.

При перезапуске службы окно Pi остаётся открытым. Новая служба подключается
к подтверждённому живому владельцу; она не восстанавливает Чифа вторым RPC-процессом.
Если окно уже закрыто, интерфейс открывается через start.cmd --session с тем же ID.

Команды кита: /kit-pause, /kit-resume, /kit-cancel, /kit-status, /kit-dashboard.
Встроенные /new и /resume относятся к разговорам Pi. Прежде чем переключить
незавершённую задачу или создать ветвь разговора, нужна подтверждённая пауза
либо отмена. Активный защитный STOP блокирует смену. Закрытие через /quit
приостанавливает незавершённую работу. Принудительное исчезновение процесса
отличается от подтверждённого завершения.

## Живая проверка

В отдельном проекте pi-native-terminal-check-20261018 был открыт настоящий Pi TUI.
Терминал показал версию 1.3.0, выбранный DeepSeek, стандартный редактор, контекст
AGENTS.md и номер задачи кита. Две строки были вставлены одним сообщением.
Чиф выполнял запрос и вызовы PowerShell в этой же сессии.

Первый запрос паузы обнаружил взаимное ожидание: обработчик события Pi читал
статус задачи, пока служба удерживала блокировку процессов и ждала abort.
Пауза осталась неподтверждённой, задача заблокировалась. Проверки журнала и
TaskControls вынесены из блокировки процессов; уведомление agent_settled
не задерживает завершение. Добавлена регрессия такого обратного вызова.

После исправления проверены подтверждённая пауза, блокировка новых работ,
перезапуск службы без закрытия терминала, повторное подключение с тем же ID,
продолжение того же разговора и отмена. Команда /new внутри Pi создала новую
сессию и отдельный журнал, сохранив старый. Проверка не выдаётся за новый
полный самостоятельный прогон разработки с двумя исполнителями.

Первое вспомогательное испытание отмены само завершило свой Python-процесс
до окончания фоновой операции. Общий контроллер обнаружил исчезнувшего владельца
и сохранил error; повторная отмена с ожиданием была подтверждена. Это отдельно
от ошибки взаимного ожидания в адаптере.

16 новых автоматических проверок охватывают endpoint, владение историей,
блокировки допуска, выбор нативного входа и сохранность обновления. Общий набор
содержит 743 тест. Полный локальный запуск завершился без падений и ошибок,
с одним системным пропуском создания символической ссылки в Windows.
Строгая оценка кита остаётся incomplete. Локальные свидетельства находятся
в .metrics/native-pi-terminal-20261018; они исключены из Git.

В повторной проверке pi-native-terminal-final-20261019 многострочный запрос
сохранился одним пользовательским сообщением, а Чиф ответил «работает». Выход
через /quit подтвердил паузу и отсоединил окно без ошибки процесса.

## Обновление проекта

Обнови шаблон и выполни из него install.cmd --update с полной папкой проекта.
Обновление проверяет хэши установочных файлов и заранее отказывается заменять
пользовательские правки. При ошибке записи уже заменённые файлы восстанавливаются.
Код приложения, ключи, выбор моделей и история не входят в заменяемую полезную нагрузку.
Открой start.cmd в обновлённом проекте и напиши ТЗ прямо в Pi.
