# Браузерная проверка и разговор после завершения

## Что теперь доступно

Обе версии используют один адаптер официального Playwright CLI 0.1.22.
Установка закреплена package-lock.json в kit/browser. npm работает локально,
без lifecycle scripts и глобальной установки. При первом браузерном действии
пакет готовится в .tools/browser рядом с китом. Установленный Pi-проект использует
папку исходного шаблона из .pi/installation.json. Кеши и временные файлы лежат
на том же диске. Нужен Node.js 18 или новее.

На Windows адаптер предпочитает установленный Edge, затем Chrome. Он создаёт
отдельный профиль в памяти; обычный профиль пользователя не подключается.
Браузер автоматически не скачивается. KIT_BROWSER_CHANNEL позволяет явно выбрать
chrome, msedge, firefox или webkit, доступный данной установке Playwright.
Linux/macOS требуют установленного поддерживаемого браузера; в этом изменении
живой запуск проверен на Windows с Edge. KIT_BROWSER_RUNTIME_HOME задаёт общую
папку пакета, если несколько шаблонов должны использовать одну установку.

## Работа Чифа

В Pi есть отдельный инструмент kit_browser. Он доступен только нативному Чифу.
В OpenCode и автоматическом режиме Pi используется тот же адаптер через CLI:

```powershell
.\kit\python.cmd -B -m kit.browser_review --task <ID> open http://127.0.0.1:8000/
.\kit\python.cmd -B -m kit.browser_review --task <ID> snapshot
.\kit\python.cmd -B -m kit.browser_review --task <ID> click "#restart-button"
.\kit\python.cmd -B -m kit.browser_review --task <ID> press ArrowUp
.\kit\python.cmd -B -m kit.browser_review --task <ID> screenshot
.\kit\python.cmd -B -m kit.browser_review --task <ID> close
```

Для видимого окна добавь --headed после URL в команде open. По умолчанию браузер
работает без окна, но исполняет страницу и отрисовывает настоящий снимок.
Навигация этого адаптера предназначена для локального HTTP-интерфейса приложения.
Имена сессий, профиль и пути снимков задаёт кит. Действия одной задачи выполняются
последовательно; другая задача имеет отдельный браузер. Новые действия запрещены
после finish, паузы и STOP; закрыть собственный браузер можно и после finish.
Через пять минут без команд фоновый браузер закрывается сам.

Ответ screenshot содержит screenshot и browser_evidence. Для завершённой записи
ux-review каждый сценарий должен содержать эти дополнительные поля:

```json
{
  "scenario": "Перезапуск",
  "actions": "Нажать Заново в открытом браузере",
  "result": "Игра вернулась к начальному состоянию",
  "browser_evidence": ".metrics/<ID>/browser/<receipt>.json",
  "visual_observation": "На снимке видны игровое поле, счёт и кнопка без перекрытия"
}
```

Свидетельство связывает задачу, браузерные действия и хэш PNG. Подмена или отсутствие
снимка, чужая задача и HTTP-сценарии без браузерного свидетельства не принимаются.
Свидетельство подтверждает браузерный запуск и сохранённый кадр; содержание
visual_observation остаётся явным утверждением проверяющего, которое можно сверить
со снимком. Старые журналы не переписываются и не получают новых доказательств.

Проверяющий должен открыть снимок и оценить внешний вид. Нативный инструмент Pi
передаёт изображение модели только когда её описание объявляет поддержку image.
Текстовая модель может проверять DOM и действия, но не должна выдавать их за
осмотр пикселей. Если снимок некому оценить, запиши ux-review --skipped с причиной.
Для модели со зрением выбирай соответствующее подключение в конфигураторе;
браузерный адаптер сам модели не заменяет. Запись skipped остаётся skipped.
Исполнители и Bug Fixer не получают браузерных инструментов или shell.

## После finish

Нативный чат Pi продолжает принимать вопросы о завершённой задаче. Доступны
чтение файлов и kit_task_report. Запись, shell, браузерные действия и новая
разработка в закрытом журнале блокируются. Для новой разработки используется /new.
Закрытие Pi не удаляет разговор.

Обе версии могут читать готовый отчёт отдельной командой:

```powershell
.\kit\python.cmd -B -m kit.task_report --task <ID> --language ru
```

Команда рендерит уже сохранённые данные finish. Она не вызывает модель, не собирает
новую статистику, не меняет журнал и не добавляет новый finish. Если сумма стоимости
не была предоставлена провайдером, она остаётся неизвестной. Токены чтения самого
отчёта и последующего обсуждения не прибавляются к закрытой задаче.

## Карта исходников

- kit/browser_runtime.py — закреплённый пакет и размещение на диске.
- kit/browser_review.py — команды, сессия браузера, снимки и свидетельства.
- kit/browser_evidence.py — проверка свидетельства перед completed.
- kit/task_report.py — чтение замороженного отчёта.
- kit/pi/chief_review_tools.mjs в Pi — инструменты Чифа поверх общего CLI.
- kit/pi/native_chief_extension.mjs в Pi — разрешение обсуждения после finish.

Живые проверки открыли завершённую игру пользователя в настоящем Edge, выполнили
клиентский JavaScript, нажали Заново и ArrowUp, сохранили и визуально просмотрели PNG.
В отдельной SDK-сессии Pi проверены наличие обоих инструментов и чтение отчёта
без запроса к модели. Исходная история пользовательского прогона не изменялась.

## Результаты проверки исправлений

19 октября 2026 года полный набор OpenCode выполнил 695 тестов за 140.306 с,
Pi — 766 тестов за 159.484 с. Оба завершились без ошибок, с одним пропуском
из-за привилегии Windows на создание символических ссылок. Строгая оценка
skipped/incomplete сохранена. Локальные журналы находятся в
.metrics/browser-report-validation-20261019/full-suite.log каждого репозитория.

Это проверки кода и отдельные живые проверки Edge и Pi SDK. Новый автономный
платный прогон Чифа после этих исправлений не выполнялся.
