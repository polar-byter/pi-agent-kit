## Границы модулей

Общая логика обращается к шлюзу выполнения. Реализации шлюза отвечают за конкретную среду. Существующий шлюз OpenCode остаётся для совместимости и сравнения. Pi работает через собственную локальную службу проекта: служба владеет RPC-процессами, подтверждает операции, сохраняет связи сессий и предоставляет состояние сторожу и дашборду.

Шлюз Pi расположен в kit/runtimes/pi_gateway.py и предоставляет PiSessionControl(root), а также collect_session_exports(root, session). Его публичные методы совпадают с существующим SessionControl: call, capabilities, sessions, tree, active, interrupt, clear_inbox, resume, prepare_resume, prepare_models, switch_model, remove. call принимает внутренние операции session.create/get/list/active/prompt/interrupt/inbox.list/inbox.cancel/remove/switchModel/permission.create и model.list. Ответы нормализованы в формат существующих потребителей журнала и дашборда. Нормализация не означает, что Pi поддерживает API OpenCode.

Служба читает подготовленные роли из .pi/kit-runtime.json. Формат: format=1, runtime="pi", roles={build/executor/executor-fast/bug-fixer: {provider, model, system_prompt, enabled}}, agent_directory — абсолютная папка конфигурации Pi. Для родительских сессий служба сохраняет корень проекта; workspace и разрешённые пути передаются отдельно. Каждый воркер получает только чтение своей копии, запись назначенного исходника и файла прогресса. Shell и вложенные агенты воркера запрещены.

Подготовку настроек предоставляет kit/pi_configuration.py: load_choices(root), prepare_pi_configuration(root, explicit_instance=None), list_available_pi_models(root), resolve_role_model_references(root, choices=None), locate_pi_command(root). Результат prepare — объект выбранного экземпляра LM Studio либо None. Конфигуратор сохраняет выбор в .pi/kit-models.json. Нативные модели имеют source="pi"; режим собственного API сохраняет baseURL/model/keyEnv. Исторический source="opencode" не преобразуется молча в доступное подключение Pi.

## Проверки и ограничения

Базовые проверки RPC, модельного каталога и расширения обходятся без генерации. Реальные модельные прогоны OpenRouter отдельно разрешены пользователем. Для проверки работы модели используется только явно выбранное и доступное подключение; отсутствие ключа нельзя выдавать за успешный модельный прогон. Настройки, кеши, журналы и установка Pi находятся на D. Не изменяем системный Python и общую установку Node.

Установлен Pi 1.3.0. Используется существующий Node 24.14.0 и отдельный Python 3.13.16 в .tools/python-runtime. Пакеты Pi занимают около 107 МиБ, Python около 111 МиБ, кеш npm около 84 МиБ; всё находится на D.
